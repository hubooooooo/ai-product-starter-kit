# AI Agent 产品上线部署手册 V1.2

> **阅读分工**：本手册由 AI 在"阶段 4 上线"和"阶段 5 收尾"读取。产品经理不读本手册，只按 AI 当时给出的"照着点"清单操作，最后照第八部分验收清单打勾；全程只贴《开始看这里》里的那句话，不需要复制任何指令。
>
> 本手册与项目根目录 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准；AI 发现冲突必须当场指出。

## 这份手册有什么用

本手册是三份手册（通用 → 前端 → 部署）的最后一份，负责把已验收的前后端变成公网可访问、有登录、数据不丢、文件不丢、出问题能查的线上产品。

默认路线是**火山引擎（Volcengine，即"火山云"）+ 函数服务 veFaaS**：不用自建服务器、不用对接公司 SSO。默认使用平台分配的 https 地址（形如 `https://xxx.apigateway-cn-beijing.volceapi.com/`），不需要自有域名。它的局限：名字不能自定义；在微信等应用内打开可能受限（待部署阶段实测确认）。要用自有域名，必须先办 ICP 备案，通常耗时数周，需要时在阶段 0 就提醒产品经理并行去办。

**关键原则**：产品经理在控制台的每一次操作，AI 都必须给出"照着点"清单，写清"去哪、点什么、填什么、看到什么算对"；产品经理遇到看不懂的界面，直接截图发给 AI。不允许让产品经理自行理解云平台概念。

### 版本说明

- **V1.2（2026-10-22）**：默认改用浏览器登录（`vefaas login --sso`），AccessKey 不再经过对话；区分"部署用密钥"和"线上运行用密钥"，收尾只删前者；部署顺序改为"先建应用 → 配环境变量 → 首次发布"，并补上最大实例数=1；写入即备份改为一致快照 + 后台顺序上传 + 多份保留 + 滞后告警；过渡档改为个人认证用户的长期方案，写明长期使用的上限与守则；新增计费项清单、余额预警、回滚与更新版本、RDS 与 VPC 接入、私有桶、限流与每日调用上限、会话密钥；删除附录固定指令、流程图、术语表和与 `AGENTS.md` 重复的底线条目；命令按 vefaas CLI 0.3.1 的帮助文本核对。

## 分工：产品经理做什么，AI 做什么

| 事项 | 谁做 | 说明 |
| --- | --- | --- |
| 注册 / 登录云账号、实名认证 | 产品经理 | AI 无法代替 |
| 浏览器授权登录（默认） | 产品经理 | AI 执行登录命令后会弹出浏览器，你登录并点"授权" |
| AccessKey（只在浏览器登录权限不够时） | 产品经理 | 你在控制台生成后**自己填进 AI 指定的本地文件**，不要贴进对话 |
| 子账号开权限 | 产品经理（主账号或管理员） | AI 给"开哪些"清单 |
| 费用确认 | 产品经理 | 每一项收费资源开通或创建前，AI 先报费用量级，你回复"确认"后才动 |
| 控制台点选（创建网关、数据库、存储桶等） | 产品经理 | AI 给"照着点"清单 |
| 安装工具、部署、配置、排错、数据持久化、文件存储、登录隔离、监控 | AI | 全部由 AI 完成 |

强制底线以 `AGENTS.md` 第 2 节为准。上线阶段最容易踩的四条，本手册在对应位置落地：密钥（第二节、第九节）、数据可恢复（第十二节）、用户只看自己的数据（第十一节）、计费先确认（第六部分）。

### 默认方案 vs 备选方案

| 能力 | 默认方案 | 触发备选的条件 |
| --- | --- | --- |
| 跑程序 | 火山引擎函数服务 veFaaS | 已有公司容器平台 / 服务器时改用 |
| 给网址 | 函数服务 + API 网关（自带 HTTPS 地址） | 已有备案域名时绑定自有域名 |
| 存文件 | 火山引擎对象存储 TOS（私有桶） | 已有公司对象存储时改用 |
| 存数据 | 生产档：云数据库 RDS PostgreSQL（需企业实名认证） | 只有个人实名认证时走过渡档：预留实例 + 写入即备份（SQLite），受第十二节的上限与守则约束 |
| 登录 | 邀请码登录（一人一码），会话放 HttpOnly Cookie，邀请码可轮换 | 已有公司 SSO 时对接 |
| 监控 | 结构化日志 + trace_id + 错误告警（Sentry 或国内替代，按决策台账 D7） | 已有公司监控平台时接入 |

**注意**：火山引擎的 RDS PostgreSQL **只对企业实名认证用户开放**。有企业认证 → 走生产档。只有个人认证 → 走过渡档，**它是个人认证用户的长期方案**：数据写入后约几秒内备份到云端，服务意外重启时最多丢失最后几秒内的写入；上限是只能单实例、不能扩容，适合内部或小范围使用（详见第十二节）。企业认证办下来后**可以**切换到 RDS，不是必须；切换前 AI 必须先给迁移方案并经产品经理确认，不是只改一个变量。

## 开局分流：先看你属于哪种情况

上线前先花 1 分钟确认"你现在手上有什么"：

| 你的情况 | 怎么判断 | 从哪一步开始 |
| --- | --- | --- |
| **A 全新**：没注册过火山引擎 | 打开 `https://console.volcengine.com` 连登录都进不去 | 从第一部分「一、账号与实名认证」开始 |
| **B 有账号**：注册过、实名过，但没开过函数服务、没建过网关 | 能登录控制台，但从没让程序跑起来过 | 从第一部分「二、登录与密钥」开始；用子账号的再做「三、子账号权限」 |
| **C 老账号**：函数服务、API 网关都开过、建过 | 控制台里能看到旧的网关 / 函数 | 产品经理仍要走「二、登录与密钥」，用子账号的确认「三、子账号权限」（API 网关、TOS、日志等权限可能从没开过）；AI 从第三部分「七、自检」开始，复用已有网关 |

**产品经理只需回答 AI 一个问题**："你现在能不能登录火山引擎控制台？里面有没有已经开好的函数服务 / API 网关？" AI 根据回答带你走对应入口。

**同时核对认证类型**：认证类型已在阶段 0 记入决策台账 D9，这里只核对。企业认证已完成 → 生产档（云数据库）；只有个人认证 → 过渡档，作为长期方案使用，企业认证办下来后可以选择切换。

## 上线要解决的 5 件事（产品语言）

1. **能被访问**——从"自己电脑上的 localhost"变成"任何人都能打开的 https 网址"，手机也能用（产品用到麦克风等能力时，浏览器要求 HTTPS）。
2. **能登录、能隔离**——区分是谁在用，A 看不到 B 的数据。
3. **数据不丢**——业务数据在服务重启、故障后还在。
4. **文件不丢**——图片、音频等大文件（按本项目实际）有地方存，换设备、清缓存都不丢。
5. **出问题能查**——程序报错能收到通知、能定位到是哪一步出的问题。

完整执行顺序见**第七部分 AI 执行总流程清单**，它是唯一的顺序来源；各节正文是每一步的展开说明。

# 第一部分：云平台准备（产品经理为主，AI 引导）

> 本部分的产品经理操作，AI 都必须给出"照着点"清单；产品经理每做一步，遇到看不懂的界面就截图给 AI。

## 一、账号与实名认证

**1. 注册 / 登录**

| 去哪 | 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| `https://console.volcengine.com` | 用手机号注册登录，或直接用飞书 / 抖音等字节系账号登录（账号体系互通） | 进入控制台首页，右上角出现你的头像 |

火山引擎和火山云是同一个平台（字节跳动旗下）。这一步 AI 无法代替。

**2. 实名认证**

| 去哪 | 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| 控制台右上角头像 → 账号管理 → 实名认证（菜单名待部署阶段实测确认，找不到就截图给 AI） | 选"个人认证"或"企业认证"，按页面提交资料 | 认证页显示"已认证" |

- **企业认证**：需要营业执照等资料，通常要等数天；能办的话建议在后端开发期就并行去办。办下来走生产档（云数据库）。
- **个人认证**：当天可完成，走过渡档，作为长期方案使用（第十二节）。之后办下企业认证，可以选择切换到生产档。

**3. 你是主账号还是子账号**：你自己注册、用手机号或飞书登录的，就是**主账号**，第三节不用做。只有公司分配给你的账号、或登录页写着"子用户 / IAM 用户"的，才是子账号。

## 二、登录与密钥

上线需要让 AI 在本机用你的身份操作云资源。有两种方式，**默认用第一种**。

**方式一（默认）：浏览器授权登录，不需要密钥**

AI 执行 `vefaas login --sso`，电脑会弹出浏览器：

| 去哪 | 点什么 | 看到什么算对 |
| --- | --- | --- |
| 自动弹出的火山引擎登录页 | 用你的火山引擎账号登录 → 点"授权 / 允许" | 页面提示授权成功，AI 那边显示登录成功 |

**方式二：AccessKey（只在方式一权限不够时用）**

CLI 官方说明：浏览器登录的授权范围可能不足以操作 API 网关等关联服务，遇到"无权操作 APIG / 权限不足"类报错时，改用 AccessKey。

AccessKey 是云账号的"操作密码"，包含 AK（`AccessKey ID`）和 SK（`Secret AccessKey`）两串字符。**不要把 AK / SK 贴进对话**，AI 也不会复述它。

推荐做法：不论你是主账号还是子账号，都单独建一个"部署用子账号"（如 `deploy-ai`），按第三节给它开权限，用它的 AccessKey。主账号的 AccessKey 拥有全部权限、无法降权，泄露风险最大。

| 步骤 | 去哪 / 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| 1 | 打开 `https://console.volcengine.com/iam/keymanage`（子账号的密钥在：访问控制 → 用户 → 选中该用户 → 密钥） | 能看到"新建密钥"按钮 |
| 2 | 点「新建密钥」 | 弹窗显示 AK 和 SK。**SK 只显示这一次**，先别关弹窗 |
| 3 | 打开 AI 在产品文件夹里建好的 `.env.deploy` 文件（AI 已确认它不会进仓库），把两串字符分别粘到 `VOLC_ACCESS_KEY_ID=` 和 `VOLC_SECRET_ACCESS_KEY=` 后面，保存 | 文件里两行等号后面都有内容 |
| 4 | 回到对话，只说"填好了" | AI 回复登录成功 |

**AI 做**：建 `.env.deploy` 前先用 `git check-ignore .env.deploy` 确认它被忽略；登录时从环境变量读取，命令行上不出现密钥明文：

```bash
set -a; . ./.env.deploy; set +a
vefaas login          # CLI 从 VOLC_ACCESS_KEY_ID / VOLC_SECRET_ACCESS_KEY 读取
vefaas whoami         # 确认当前凭据状态
```

登录成功后，凭据已由 CLI 加密保存在本机，AI 删除 `.env.deploy`。

**线上运行用的密钥（和上面不是同一把）**

产品用到对象存储时（第十三节；过渡档的数据备份也用它），线上程序自己需要一把密钥去读写存储桶。这把密钥**单独建、单独管**：

- 新建一个子账号（如 `app-runtime`），**只给对象存储 TOS 的权限**，能限定到本项目的桶最好。
- 为它生成 AK / SK，按上表同样的方式填进 AI 建好的 `.env.runtime`，AI 把它导入线上环境变量（第九节）后删除本地文件。
- **收尾时不删这把**。删了它，线上备份和文件读写会立刻失效。收尾只删"部署用"的那把（第七部分）。

## 三、子账号权限（只有用子账号时才需要）

> 主账号跳过本节。子账号不能给自己开权限，必须由主账号或管理员操作。

子账号默认几乎没有权限，需要逐个开通。部署用子账号通常需要以下服务的**完整权限（FullAccess）**：

| 服务 | 搜索关键词 | 作用 | 什么时候要 |
| --- | --- | --- | --- |
| 函数服务 veFaaS | 函数 / veFaaS | 跑程序 | 必开 |
| API 网关 APIG | API 网关 / APIG | 给网址；`deploy --newApp` 绑定网关需要 | 必开 |
| 对象存储 TOS | TOS / 对象存储 | 存文件、存备份 | 用到存储或过渡档时 |
| 日志服务 TLS | 日志 / TLS | 查平台日志 | 要看平台日志时 |
| 云数据库 RDS | RDS / 数据库 | 存数据 | 生产档 |
| 私有网络 VPC | 私有网络 / VPC | 云数据库所在的"内部局域网" | 生产档 |
| 访问控制 IAM（只读） | 访问控制 / IAM | 让 AI 查询身份和权限是否生效 | 建议（策略名待部署阶段实测确认） |

镜像仓库 CR 只在用镜像部署时才需要，本手册默认不用，不开。

线上运行用子账号（`app-runtime`）**只开对象存储 TOS**，不开其他。

| 去哪 | 点什么 | 看到什么算对 |
| --- | --- | --- |
| 控制台 → 访问控制 → 用户 → 找到对应子账号 → 权限 → 添加权限 | 逐个搜索上表关键词，勾选带 "FullAccess" 的策略（不要选 ReadOnly，IAM 那项除外） | 该子账号的权限列表里出现所选策略名 |

开完告诉 AI，AI 会逐个服务调接口确认生效。

# 第二部分：部署工具（AI 为主）

> 本部分全部由 AI 在本地执行，产品经理无需操作。

## 四、veFaaS CLI

```bash
npm i -g @volcengine/vefaas-cli
vefaas --version   # 本手册命令按 0.3.1 的帮助文本核对，建议 >= 0.3.1
```

## 五、veFaaS AI Skill（重要）

veFaaS 提供了专门教 AI 部署的"技能包"，装了之后 AI 能直接查到官方部署规范：

```bash
vefaas skills update
```

它会安装到本机 `~/.agents/skills/vefaas/`，包含应用部署、函数管理、认证、排错等参考文档。**AI 在开始部署前必须先安装并阅读这个 Skill。** 使用不识别该目录的编码工具时，AI 直接用文件读取方式打开其中的参考文档。命令写法与本手册不一致时，以 `vefaas <命令> --help` 的输出为准。

## 六、登录

按第二节执行。常用检查命令：

```bash
vefaas login --sso   # 默认：浏览器授权
vefaas whoami        # 查看当前凭据状态
vefaas doctor        # 全面检查环境、凭据、项目、连通性
```

`vefaas login --check` 只校验凭据、不保存，不用来判断"已经登录"。

# 第三部分：部署全流程（AI 为主，产品经理配合点几下）

## 七、自检项目与检测框架

**AI 做**：

1. 在本地运行 `./verify.sh <产品名>`（这时还没有阶段 4 的证据包，先不带阶段名），各项通过（或不适用）才继续。
2. 在后端目录运行 `vefaas inspect`，检测框架、构建命令、启动命令、端口。检测不到框架（入口不在根目录 `main.py` 时常见）就显式指定启动命令，不要猜。
3. 检查配置读取方式：**数据目录、文件目录必须能由环境变量指定，且不得在 import 时就创建目录**。veFaaS 实例除 `/tmp` 外只读，import 时建目录会在启动瞬间报只读错误，配了环境变量也没用；发现这种写法先改代码。

**常见正确启动命令**（FastAPI 项目，代码在 `app/main.py`）：

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

用 `python -m uvicorn` 而不是 `uvicorn`：线上实例里 `uvicorn` 命令可能不在 PATH。

**打包排除**：以下内容不得被打包上传：`.venv/`、`data/`、`__pycache__/`、`.pytest_cache/`、`.env` 和所有 `.env.*`（`.env.example` 除外）、`.vefaas/`。在后端目录维护 `.gitignore` 和 `.vefaasignore`（veFaaS CLI 打包时用它排除文件），**部署前确认 `.vefaasignore` 文件名正确、确实生效**。

**运行时版本**：选 Python 3.12 对应的运行时，与通用手册默认的 Python 3.12.x 一致；运行时标识以 `vefaas inspect` 或 `vefaas fn info` 的输出为准（具体名称待部署阶段实测确认）。现有项目若用的是其他版本，部署前必须在 3.12 下跑一遍测试。

## 八、创建 API 网关实例（产品经理配合点几下）

应用需要一个"访问入口"，即 API 网关实例。**没有网关，应用无法创建。**

**AI 做**：先查有没有可用网关：

```bash
vefaas gateway list --first
```

返回空才需要创建。默认由产品经理在控制台创建（用 OpenAPI 创建参数复杂，非必要不用）。

**创建前**：AI 先按第六部分告知网关的计费方式和量级，产品经理回复"确认"后再开始点。

**产品经理照着点**：

| 步骤 | 去哪 / 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| 1 | 控制台顶部搜索"API 网关"并打开（地址待部署阶段实测确认） | 进入 API 网关页面 |
| 2 | 如提示"开通服务"：先停下告诉 AI，AI 报费用、你确认后再点开通（按量计费） | 页面不再提示开通 |
| 3 | 点「创建实例」，按下一张表填 | 进入创建表单 |
| 4 | 点确定，等待创建完成（通常不超过 10 分钟，待实测） | 实例列表里新实例状态变为"运行中" |
| 5 | 把实例名称告诉 AI | AI 回复已找到网关 |

| 选项 | 选什么 |
| --- | --- |
| 地域 | 与函数服务同地域（默认华北2 北京） |
| 网关类型 | **Serverless 网关**（专门对接函数服务，便宜、简单；不要选标准型，那是给容器 / 服务器用的，更贵） |
| 实例名称 | 自定义，如 `product-gw` |
| 网络类型 | **公网**（否则外面访问不到） |
| 监控告警 / 日志服务 / 链路追踪 三个开关 | 验证阶段**全部拨到关闭**（省钱；程序自身日志够排错）；正式对外前再按需打开 |
| 其他 | 保持默认 |

控制台里看到旧的"创建失败"网关，不用管，直接创建新的。

## 九、创建应用并配置线上环境变量（首次发布之前）

> ⚠️ **环境变量必须在首次发布之前配好**，否则应用一启动就会崩溃（例如数据库写到只读目录）。环境变量只能配在已经存在的应用上，所以顺序是：**先建应用（不发布）→ 配环境变量 → 首次发布（第十节）**。

**第一步：建应用，不发布**

在后端目录执行（`link --newApp` 只创建应用并绑定当前目录，不触发发布；已按 CLI 0.3.1 帮助核对）：

```bash
vefaas link \
  --newApp <应用名> \
  --gatewayName <网关名> \
  --command "python -m uvicorn app.main:app --host 0.0.0.0 --port 8000" \
  --port 8000 \
  --memory <MB> --cpu <毫核>
```

`--memory` / `--cpu` 选能跑起来的最小规格（CLI 默认 1024MB / 500 毫核），规格决定按量费用和预留实例费用，选定前告知产品经理。

如果 `link --newApp` 之后 `vefaas env list` 提示找不到函数（首次未发布时是否已生成函数，待部署阶段实测确认），改用后备顺序：`vefaas deploy --newApp ...` 首次发布（允许这次启动失败）→ 配环境变量 → `vefaas deploy --skipbuild --yes` 重新发布。

**第二步：配环境变量**

应用启动依赖的配置一律通过**环境变量**配到线上（环境变量就是程序的"配置开关"：密钥、数据库放哪、要不要强制登录，都不写死在代码里），不能依赖本地 `.env`（它不打包、不进线上）。

含密钥的值不要写在命令行上。做法：AI 在产品文件夹里生成 `.env.prod`（确认被 `.gitignore` 忽略），密钥类的值由产品经理按第二节的方式自己填，然后导入并删除本地文件：

```bash
vefaas env import --file ../.env.prod   # 合并导入；要整体替换线上变量时才加 --replace
rm ../.env.prod
vefaas env list                          # 核对键名都在
```

`vefaas env list` 的输出可能含明文值，**不要贴进对话或证据包**，只核对键名。

**环境变量清单**（键名以本项目代码实际读取的为准，下表是常见示例）：

| 环境变量 | 配什么 | 为什么 |
| --- | --- | --- |
| `DATABASE_URL` | 生产档：RDS PostgreSQL 连接串；过渡档：`sqlite:////tmp/data/app.db`（绝对路径要 4 个斜杠） | 实例除 `/tmp` 外只读；连接串含密码，只能配在环境变量 |
| 数据 / 文件目录（示例：`DATA_DIR=/tmp/data`） | `/tmp` 下的目录 | 同上；接对象存储前文件也只能放 `/tmp` |
| 会话签名密钥（示例：`SESSION_SECRET`） | AI 生成的随机长串 | 不配或启动时随机生成，每次发布全员掉线 |
| 运行模式开关（示例：`ENV=prod`，项目有这个开关时才配） | `prod` | 例如打开强制登录 |
| `INVITE_CODES` | 邀请码列表（第十一节） | 换码只需更新变量并重新发布 |
| 模型 Key 等密钥类 | 原样配置 | 不写进代码 |
| 对象存储相关（第十三节） | 运行时子账号的 AK / SK、桶名等 | 线上读写文件和备份 |

`/tmp` 的容量有上限（具体大小待部署阶段实测确认，可用 `vefaas fn exec --id <函数ID> -- df -h /tmp` 查看）。数据库和临时文件加起来接近上限前，必须切到云数据库或对象存储。

## 十、首次发布、实例数与访问地址

**第一步：首次发布（不带预留实例）**

```bash
vefaas deploy --yes        # 在已 link 的后端目录执行
```

> ⚠️ 实战经验：**首次发布不要带 `--minInstance`**，否则报 `Function ... not deployed`（函数还没有初始版本，设不了实例数）。

**第二步：设实例数（过渡档必做，先确认费用）**

预留实例 = 让函数服务**至少常驻一个实例不关机**，保证 `/tmp` 里的数据不因空闲被回收。它按规格和时长持续计费，是过渡档最主要的长期费用，**设之前 AI 必须按第六部分告知量级并等产品经理确认**。

```bash
vefaas fn scale --id <函数ID> --min 1 --max 1    # 过渡档：最少 1 个、最多 1 个
vefaas fn scale --id <函数ID>                     # 查看，确认 Min=1、Max=1
```

过渡档的**最大实例数必须是 1**：实例一旦超过 1 个，每个实例各有一份数据库，用户数据会串号。生产档接 RDS 后，`--max` 按需设置，`--min` 可保留 1 以减少冷启动。函数 ID 在 `.vefaas/config.json` 或 `vefaas config list` 里。

**第三步：请求超时与流式输出**

模型生成可能要几十秒甚至更久。用 `vefaas fn config --id <函数ID> --requestTimeout <秒>` 把函数请求超时设得大于最长一次模型调用。API 网关自身的超时上限、以及是否原样透传 SSE 流式输出，待部署阶段实测确认：发布后用 `curl -N <访问地址>/<流式接口>` 打一次，确认内容逐段到达，且以 `done` 或 `error` 事件收尾。

**第四步：拿访问地址**

```bash
vefaas domains
```

**判断部署这一步成没成，只看网址能否打开**：控制台状态字段可能滞后（还显示"失败"，网址其实已能访问）。**上线完成另有标准：第八部分验收清单全过才算。**

**发布卡在"滚动中"**（滚动发布 = 新版本逐步替换旧版本的过程）：报 `can not release function when function is releasing` 或 `Release is in rolling status` 时，先别反复发布：

```bash
vefaas fn release-record status --id <函数ID>    # 看状态，等它自己结束
vefaas api AbortRelease --FunctionId <函数ID>    # 仍卡住再中止（参数名待部署阶段实测确认）
```

**发布后验收失败就回滚**：

```bash
vefaas fn revision --help                    # 查看历史版本的子命令
vefaas fn rollback <版本号> --id <函数ID>     # 回滚到上一个正常版本
```

### 更新版本（已上线后再发布）

代码改了要重新上线时，保持原有环境变量、启动命令和访问地址不变，按以下顺序：

1. 本地跑 `./verify.sh <产品名> 阶段4`，通过才继续。
2. 过渡档：先触发一次"立即备份"并确认成功，再开启维护模式暂停写入（第十二节）。
3. 在已 link 的目录执行 `vefaas deploy --yes`，**不带 `--newApp`**（带了会新建一个应用和新地址）。
4. 发布后验收：能登录、历史数据都在、核心链路跑通；过渡档关闭维护模式。
5. 任一项不过，立即 `vefaas fn rollback` 回到上一版，再排查。

### 前端（Next.js）应用单独部署

有正式前端时，前后端是**两个独立应用**，分别部署、各自有地址。前端通过 `rewrites` 同源代理到后端，避免跨域问题。

**部署前改造（AI 在 `frontend/` 目录完成）**：

1. `next.config.ts` 设 `output: "standalone"`，并把"指向哪个后端"做成环境变量（如 `BACKEND_URL`）。
2. 构建命令在 build 后拷贝静态资源和公共资源：`npm run build && cp -r .next/static .next/standalone/.next/static && cp -r public .next/standalone/public`（不拷 `public/`，图标和图片会 404）。
3. 启动命令用 `node server.js`，端口 3000。
4. 本地开发的前端配置放在 `frontend/.env.local`，必须被 `.gitignore` 忽略（根目录 `.gitignore` 的 `.env.*` 规则已覆盖，AI 用 `git check-ignore frontend/.env.local` 确认）；线上不读这个文件。
5. 字体：国内构建环境访问 Google 字体服务不稳定，`next/font/google` 会在 `next build` 时联网下载字体，可能导致构建失败。优先用 `next/font/local` 加载放在项目里的字体文件。

**关键坑：构建时环境变量**——`rewrites` 的目标地址在 build 时固化，所以 `BACKEND_URL` 必须在**执行部署命令时**一并注入，而不是部署后再 `vefaas env set`（那只对运行时生效，改不了已固化的 rewrites）。后端地址一旦变化，前端必须带上新的 `BACKEND_URL` **重新构建并发布**。

```bash
cd frontend
BACKEND_URL="https://后端访问地址" vefaas deploy \
  --newApp <前端应用名> \
  --gatewayName <网关名> \
  --buildCommand "npm run build && cp -r .next/static .next/standalone/.next/static && cp -r public .next/standalone/public" \
  --outputPath ".next/standalone" \
  --command "node server.js" \
  --port 3000 \
  --yes
```

前端地址是对用户公布的正式入口；后端地址只用于排错，不对外公布。上线后验证：前端页面能打开、`/api/*` 能代理到后端（登录、取数正常）、产品用到的设备能力（如麦克风）在 HTTPS 下可用、移动端真机走一遍。

# 第四部分：上线后必做（AI 为主）

## 十一、登录与数据隔离

上线后必须做到"用户只能看自己的数据"。默认采用**邀请码登录**：

- **一人一码、码即身份、不得共用**：每个邀请码对应一个用户记录，两个人共用一个码就是同一个用户，隔离失效。分发时向产品经理讲清这一点。
- 后端提供登录接口，邀请码换取会话；会话放在 Secure、HttpOnly、SameSite 合理配置的 Cookie 中，前端不自行保存 token（与前端手册第 18.2 节一致）。前后端分属两个地址时，由前端的同源代理转发 `/api/*`，Cookie 落在前端地址下。
- 所有数据接口按当前登录用户过滤；访问他人数据返回 403；权限判断在后端。
- 邀请码**由 AI 生成，单独发给产品经理分发**；通过环境变量 `INVITE_CODES` 预置。码本身不写入仓库和 `docs/项目状态.md`，状态文件只记分发记录（给了谁、什么时候）。
- **可轮换**：更新环境变量并重新发布即可作废旧码。给同一个人换码时，把新码绑到他原来的用户记录上，不要新建用户，否则他的历史数据会"看不见"。
- **防刷**：登录失败限流（示例：同一来源连续失败 5 次，锁定 15 分钟）；每个用户每天的模型调用次数设上限，数值按决策台账 D4 的成本上限换算，经产品经理确认。

**AI 做**：部署后验证——未登录访问被拒、错误邀请码被拒、正确邀请码能登录；用两个不同的码在两个无痕窗口各登录一次，A 看不到 B 的数据；连续输错触发限流。

## 十二、数据持久化（关键）

两档的区别：生产档 = 企业认证 + 云数据库，可随用户量扩容；过渡档 = 个人认证 + 实例本地 SQLite + 写入即备份到对象存储，是个人认证用户的长期方案，只能单实例、不能扩容。

### 生产档：云数据库 RDS PostgreSQL

**创建前**：AI 按第六部分告知 RDS 的计费方式与量级，产品经理确认。

**产品经理照着点**（菜单名待部署阶段实测确认，看不懂就截图）：

| 步骤 | 去哪 / 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| 1 | 控制台搜索"云数据库 PostgreSQL"并打开 → 点「创建实例」 | 进入创建表单 |
| 2 | 地域：与函数服务同地域；私有网络 VPC 和子网：选 AI 告诉你的那个（VPC 是云上的"内部局域网"，数据库放在里面外网访问不到） | 表单里地域和网络已选好 |
| 3 | 规格：最小规格；计费方式：按量（或 AI 推荐的方式） | 页面显示的价格与 AI 报的量级一致 |
| 4 | 数据库账号密码：密码由你自己想好，按第二节的方式填进 AI 建好的本地文件，不要贴进对话 | — |
| 5 | 白名单：加入 AI 给你的函数所在网段 | — |
| 6 | 点创建，等待完成 | 实例状态变为"运行中"，把实例名称告诉 AI |

**AI 做**：

1. **函数接入 VPC**：函数默认访问不到 VPC 内的数据库，必须给函数配置同一个 VPC 和子网：`vefaas fn config --id <函数ID> --vpcJson '<VpcConfig JSON>'`（参数已按 CLI 帮助核对，JSON 字段待部署阶段实测确认）。
2. 把连接串配到环境变量 `DATABASE_URL`（第九节方式）。
3. **连通性验证**：应用的健康检查接口执行一次 `SELECT 1`，发布后访问它确认返回正常。
4. 开启 RDS 自带的自动备份。

**从过渡档切换到生产档（可选，不是必须）**：SQLite 到 PostgreSQL 是数据迁移，不是只改 `DATABASE_URL`（自增、布尔、JSON、时间类型都有差异）。切换前 AI 先给迁移方案（导出、导入、字段差异处理、失败如何回滚），产品经理确认后执行；完成后验证登录和历史数据都在。

### 过渡档：预留实例 + 写入即备份（个人认证用户的长期方案）

veFaaS 实例的 `/tmp` 是**临时存储**：实例缩容或重建后数据丢失。过渡档靠下面三件事让数据长期可恢复。过渡档依赖对象存储桶，**先完成第十三节第 1 到 3 步**。

**1. 预留实例常驻**：按第十节第二步设 `--min 1 --max 1`，保证有一个实例持续运行，`/tmp` 不因空闲被回收。

**2. 写入即备份**（AI 实现，要点缺一不可）：

- **一致快照**：不直接拷贝 `app.db` 文件（WAL 模式下刚提交的数据在 `app.db-wal` 里，直接拷会丢；写入中途拷会得到半截文件）。用 Python 标准库 `sqlite3` 的 `Connection.backup()`，或执行 `VACUUM INTO '/tmp/snapshot.db'`，先生成一份一致的快照文件再上传。
- **后台顺序上传**：业务写入提交后，只把"有未备份数据"的标记置上并唤醒唯一的后台上传任务，不在请求里同步上传（避免拖慢接口）。上传任务每次取最新快照上传；上传期间又有新写入，就在完成后再传一次。这样多次写入会自动合并，并且严格按顺序上传，不会出现旧快照覆盖新快照。
- **多份保留**：对象键带单调递增序号或 UTC 时间戳，如 `db_backup/app-<序号>.db`，再写一个 `db_backup/latest.json` 指向最新一份；保留最近 20 份（示例值），或者开启桶的版本控制。一份坏快照不会覆盖掉唯一的好备份。
- **失败重试与告警**：上传失败独立退避重试（如 1 秒、2 秒、4 秒……上限 60 秒），每次失败记错误日志；**有未备份写入、且距最近一次成功备份超过 60 秒，视为故障**，按第十四节发出告警。
- **发布前最终备份**：更新版本前（第十节"更新版本"），先触发一次立即备份并确认成功，再开启**维护模式**：写接口暂时返回 503 和"系统维护中，请稍后"提示，读接口照常。新实例恢复完成后关闭维护模式。

**3. 启动自动恢复**：服务启动时，本地数据库不存在而云端有备份，就下载 `latest.json` 指向的快照恢复，恢复完成后才开始接受请求。上传时比对序号：不允许上传序号小于云端最新序号的快照，防止新旧实例交替时回退。

**对产品经理的承诺（AI 必须原样告知）**：写入后约几秒内备份到云端；服务意外重启时，最多丢失最后几秒内的写入。

**长期使用的上限与守则（AI 必须原样告知产品经理，这些是过渡档能长期用的条件）**：

| 项目 | 规则 |
| --- | --- |
| 实例数 | 只能单实例，最大实例数必须是 1 |
| 扩容 | 不能随用户量扩容 |
| 适用规模 | 同时在线约几十人以内的内部或小范围使用；超过就必须切到生产档（需企业认证）或换平台 |
| 数据库大小 | 数据库文件超过约 200MB 必须切换方案（快照上传变慢，备份会跟不上） |
| 备份监控 | 备份滞后超过 60 秒即告警，AI 收到告警必须排查 |
| 每月人工导出 | 每月一次，AI 提醒产品经理把最新备份下载到自己电脑保存（步骤见下表） |

**每月人工导出：产品经理照着点**

| 步骤 | 去哪 / 点什么 | 看到什么算对 |
| --- | --- | --- |
| 1 | 控制台搜索"对象存储 TOS"并打开 → 进入本项目的桶（桶名 AI 会告诉你） | 看到文件列表 |
| 2 | 打开 `db_backup` 文件夹 → 按修改时间排序，找最新的一份 `app-<序号>.db` | 最新一份的修改时间接近当前时间 |
| 3 | 勾选它 → 点「下载」 | 浏览器下载了一个 `.db` 文件 |
| 4 | 把文件移到电脑上固定的文件夹（如"产品备份"），文件名前加上日期 | 文件夹里多了这个月的备份 |

AI 在 `docs/项目状态.md` 记录每次导出的日期；超过 35 天没导出，下次会话开头先提醒。

## 十三、文件上对象存储

图片、音频等大文件（按本项目实际），上线后必须从本地目录迁移到对象存储，否则换设备、实例重建后文件丢失：

1. **创建前**：AI 按第六部分告知存储容量、请求次数和外网下行流量的计费方式，产品经理确认。
2. **创建桶**：桶必须设为**私有**（公开桶等于所有用户的文件任何人都能下载）。桶名要求小写字母、数字、连字符，且全局唯一（可用账号 ID 做后缀）。
3. **线上凭证**：用第二节的"线上运行用子账号"的 AK / SK，配置环境变量：`STORAGE_PROVIDER=s3`、`S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET`、`S3_REGION`（示例键名，以项目代码为准）。
4. **代码层**：通过存储抽象读写对象（本地 / S3 兼容协议可切换）。用户下载文件走**预签名 URL**（有效期短，如 10 分钟），并且只给当前用户自己的文件签名。

**TOS 的 S3 兼容参数**：

- 访问地址（endpoint）是 `https://tos-s3-cn-beijing.volces.com`（注意带 `tos-s3-` 前缀）。
- 客户端要显式指定 `signature_version="s3v4"` 和 `addressing_style="virtual"`。

## 十四、日志与错误监控

1. **结构化日志 + trace_id**：每个请求生成 trace_id（每个请求的"追踪号"，出问题能串起来查是哪一步），串联模型调用、检索等各环节。日志只记元信息（示例：会话 ID、耗时、调用次数），不记密钥、密码和完整用户文档。
2. **看函数日志**：`vefaas fn logs --id <函数ID> --lines 50`。
3. **错误告警**：先看决策台账 D7（数据能否出境）。
   - D7 不允许出境：sentry.io 的服务器在境外，不能用；改用火山引擎日志服务 TLS 的告警，或自建 Sentry 放在国内。
   - 允许出境、使用 Sentry：配置 `SENTRY_DSN`，必须关闭 `send_default_pii`，并在上报前脱敏请求内容。
   - 告警通知到产品经理能收到的渠道（邮件 / 企微 / 飞书）；过渡档的"备份滞后"告警走同一渠道。
4. 网关的监控、日志、链路追踪三个开关，正式对外前按需打开，打开前同样先告知费用。

# 第五部分：排错清单（常见问题与处理）

每条按「现象 → 原因 → 解决」组织。AI 遇到类似报错时直接对照。

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 部署后启动报 `uvicorn: command not found` | 函数实例 PATH 里没有 uvicorn 命令 | 启动命令改用 `python -m uvicorn ...` |
| 启动报 `OSError: Read-only file system` | 实例除 `/tmp` 外只读，代码写到了只读目录 | 数据库 / 文件目录改为 `/tmp` 下，如 `sqlite:////tmp/data/app.db` |
| 配了 `DATABASE_URL` 仍报 `PermissionError: Permission denied` | 代码在 import 时按默认路径建目录，早于读取环境变量 | 改代码：目录由环境变量指定，不在 import 时创建（第七节） |
| 首次部署报 `Function ... not deployed` | 首次部署就带了 `--minInstance`，函数还没有初始版本 | 首次部署**不带** `--minInstance`；成功后再 `vefaas fn scale --min 1 --max 1` |
| `vefaas env list` / `env set` 找不到应用或函数 | 应用还没创建 | 先 `vefaas link --newApp` 建应用；仍不行按第九节后备顺序 |
| 控制台显示"部署失败"，但网址其实能打开 | 状态字段滞后 | 部署这一步以网址能否打开为准；上线完成仍以第八部分验收清单为准 |
| 部署报 `Release is in rolling status` / `can not release function when function is releasing` | 上一次发布卡在滚动状态 | 别反复发布；`vefaas fn release-record status --id <函数ID>` 等它结束，仍卡住再 `vefaas api AbortRelease --FunctionId <函数ID>` |
| 发布后功能异常 | 新版本有问题 | `vefaas fn rollback <版本号> --id <函数ID>` 回到上一版 |
| 浏览器登录后报"无权操作 APIG / 权限不足" | SSO 授权范围不够 | 按第二节方式二改用部署用子账号的 AccessKey |
| `vefaas inspect` 检测不到框架、启动命令误判 | 项目入口不在根目录 | 显式 `--command "python -m uvicorn app.main:app ..."` |
| 打包上传了几百 MB | `.venv`、`data` 没被排除 | 用 `.gitignore` / `.vefaasignore` 排除 `.venv`、`data`、`.env*`、`.vefaas` |
| 密钥泄露进代码包 | `.env` 被打包 | 确保 `.env` 和 `.env.*` 在排除列表；线上配置走环境变量 |
| 子账号调接口报 `AccessDenied` / `not authorized` | 子账号默认无权限 | 按第三节清单逐个开 FullAccess（含 API 网关） |
| 云数据库 PostgreSQL 提示"只对企业用户开放" | RDS PostgreSQL 需企业实名认证 | 个人认证走过渡档（长期方案，第十二节）；企业认证办下来后可以选择切换 |
| 函数连不上 RDS | 函数没接入数据库所在 VPC，或白名单没放行 | 第十二节生产档 AI 做第 1 步；检查白名单 |
| TOS 报 `Bad Request` / `InvalidPathAccess` | endpoint 或 addressing style 不对 | endpoint 用 `https://tos-s3-cn-beijing.volces.com`；客户端指定 `s3v4` + `addressing_style="virtual"` |
| 收尾后备份突然全部失败 | 删掉的是"线上运行用"的那把 AccessKey | 重新为运行时子账号生成密钥并导入线上环境变量；以后收尾只删部署用的那把 |
| 日志出现"备份滞后超过 60 秒"告警 | 上传持续失败（凭证失效、桶权限、网络、数据库过大） | 按日志里的错误逐项排查；数据库接近 200MB 时切换方案 |
| 创建 VPC 用 POST 报 `action does not exist` | 部分火山引擎 OpenAPI action 只认 GET（待部署阶段实测确认） | 改用 GET 方式传参数 |
| `vefaas gateway list --first` 返回空 | 没有可用网关实例 | 让产品经理在控制台创建 Serverless 网关（第八节） |
| 登录后看到他人数据 / 数据串号 | 数据接口未按用户隔离，或过渡档实例数超过 1 | 接口按当前登录用户过滤；确认 `vefaas fn scale` 显示 Max=1 |
| 部署成功后数据隔段时间就丢 | `/tmp` 是临时存储，实例被回收，且备份未生效 | 确认 `--min 1 --max 1`、写入即备份和启动恢复都已实现 |
| 网站突然打不开、控制台提示欠费 | 账户余额不足，按量资源被停止 | 产品经理充值；第六部分设好余额预警 |

# 第六部分：费用与账单

手册不预设单价，价格以火山引擎官网当时的价格页为准。AI 在"上线方案摘要"里按下表逐项估算量级（每月大约多少钱），每一项**开通或创建前**都要再告知一次，产品经理回复"确认"后才动。

| 计费项 | 什么时候产生 | 怎么计费（以官网为准） | 省钱做法 |
| --- | --- | --- | --- |
| 预留实例 | 过渡档必开；生产档可选 | 常驻实例按规格 × 时长持续计费，不用也收 | 选能跑起来的最小 `--memory` / `--cpu` |
| 函数调用 | 有人访问就产生 | 按请求次数与执行时长 | 无 |
| API 网关（Serverless） | 开通网关后 | 按调用量（是否有实例费待部署阶段实测确认） | 验证阶段关掉三个可观测性开关 |
| 对象存储 TOS | 存文件、过渡档备份 | 存储容量 + 请求次数 + 外网下行流量 | 备份只保留最近 N 份 |
| 云数据库 RDS | 生产档 | 按实例规格，包月或按量 | 先选最小规格 |
| 日志服务 TLS | 打开平台日志 / 告警时 | 按日志量 | 只记元信息，不记全文 |
| 公网流量 | 用户下载大文件时 | 按流量 | 大文件走对象存储预签名下载 |

**产品经理照着点：看账单、设余额预警**（菜单名待部署阶段实测确认）

| 步骤 | 去哪 / 点什么 / 填什么 | 看到什么算对 |
| --- | --- | --- |
| 1 | 控制台右上角「费用」→ 费用中心 → 账单 | 看到按产品列出的本月费用 |
| 2 | 费用中心 → 余额预警（或"可用额度提醒"）→ 开启，阈值填 AI 建议的金额（约一周的预估费用） | 预警状态显示"已开启" |

**欠费会停服**：余额不足时，按量计费的资源会被停止，网站打不开；长时间欠费，资源和数据可能被释放（具体时限以官网为准）。过渡档的数据靠实例和对象存储，欠费风险更大，余额预警必须设。
